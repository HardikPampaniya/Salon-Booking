# API reference

All routes are under `/api`. Errors use `{ "error": { "code": "...", "message": "..." } }`. Customer booking responses are not cached and require the booking’s secret management token. No public booking-list or admin endpoint exists.

## Public endpoints

| Method and path | Purpose |
|---|---|
| `GET /api/health` | Sanitized database, payment and booking status. |
| `GET /api/booking/readiness` | Non-secret setup issues and whether booking can be enabled. |
| `GET /api/config` | Public salon identity, schedule and timezone. |
| `GET /api/services` | Canonical service catalog and category groups. |
| `GET /api/availability?serviceId=id&date=YYYY-MM-DD` | Availability for one service. |
| `GET /api/availability?serviceIds=id1&serviceIds=id2&date=YYYY-MM-DD` | Availability for a cart. |

Availability requires all selected services to be active, price-approved, positive-duration, and bookable. The API returns only appointment starts where one qualified active employee can perform the whole cart for the combined duration. It respects salon/staff schedules, breaks, blocked periods, leave, confirmed appointments, and unexpired holds. It returns no bookable times while readiness is disabled; it does not advertise schedule-only times as reservable.

The date uses the salon timezone. The default booking horizon is 60 days. Availability contains `durationMinutes`, start/end timestamps, and an available staff count, but does not expose employee names or offer customer employee choice.

## Create a booking hold

### `POST /api/bookings/holds`

Creates a temporary 10-minute hold, automatically assigns one qualified employee, reserves their 15-minute lock segments, and creates one Razorpay order for the fixed INR 100 advance. The one assigned employee must be eligible for every service in the cart. Requires `Idempotency-Key` with 16–100 characters.

```json
{
  "serviceIds": ["service-id-from-catalog", "another-service-id"],
  "date": "YYYY-MM-DD",
  "startAt": "ISO-8601 appointment-start timestamp returned by availability",
  "name": "Customer name",
  "phone": "+91 9876543210",
  "email": "optional@example.com",
  "whatsappUpdatesOptIn": false,
  "managementToken": "32-byte random token generated by the browser",
  "policyAccepted": true
}
```

The API accepts 1–20 distinct service IDs; for backwards compatibility it also accepts the earlier single `serviceId`. The server calculates service subtotal, combined duration, and fixed advance. It ignores browser-submitted amounts. The hold response includes the Razorpay public Key ID, order ID, INR amount, appointment interval, assigned staff name, and private management token. Never log/share the token.

Examples of errors include `BOOKING_NOT_READY`, `SALON_CONFIGURATION_INCOMPLETE`, `ARRIVAL_TIME_UNAVAILABLE`, `STAFF_UNAVAILABLE`, `IDEMPOTENCY_KEY_REUSED`, and `PAYMENT_ORDER_UNAVAILABLE`.

## Payment confirmation and management

### `POST /api/bookings/verify-payment`

Accepts Checkout’s order ID, payment ID, and signature. The server validates the checkout HMAC, fetches payment state from Razorpay, and matches the expected order, amount (10,000 paise), and currency (INR). The appointment is confirmed only after trusted capture verification.

### `POST /api/bookings/manage`

Returns one booking’s status with its `reference` and `Authorization: Bearer <managementToken>`. The token is random and stored hashed. The response gives the appointment start/end, service/duration snapshot, assigned employee, advance/refund state, and cancellation eligibility.

### `POST /api/bookings/cancel`

Uses the same private token. Customer cancellation is permitted at least 60 minutes before appointment start. A qualifying cancellation releases employee reservation locks and requests a refund of the captured advance to the original payment method. Refund status remains pending until provider reconciliation; uncertain outcomes require manual review. The API does not claim a refund succeeded merely because Razorpay accepted a request. Rescheduling is not implemented.

## Razorpay webhook

### `POST /api/webhooks/razorpay`

Receives the exact raw JSON body and validates `X-Razorpay-Signature` using `RAZORPAY_WEBHOOK_SECRET`. Event IDs are deduplicated. Subscribe to:

- `payment.authorized`
- `payment.captured`
- `payment.failed`
- `refund.processed`
- `refund.failed`

Use separate Test and Live webhooks/secrets. See `RAZORPAY_SETUP_GUIDE.md` for the exact staging and production setup.

## Important states

- Booking: `held`, `confirmed`, `cancelled`, `expired`, `manual_resolution`.
- Payment: `order_pending`, `order_creating`, `created`, `authorized`, `captured`, `failed`, `refund_pending`, `refunded`, `refund_failed`, `manual_review`.
- Refund: `pending`, `submitting`, `processing`, `processed`, `failed`, `manual_review`.
- Notification: `pending`, `sending`, `accepted`, `mocked`, `manual_review`. `accepted` means a provider accepted the request, not that it reached a recipient; `mocked` means no message was sent.

An uncertain refund API result is not retried automatically. Check Razorpay before any manual action. The public booking gate remains off until the full readiness report is clear and the salon owner approves launch.
