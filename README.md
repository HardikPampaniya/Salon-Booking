# The Dream Beauty Unisex Studio

React/Vite website and Express/MongoDB booking API for the studio in Karanjade, Navi Mumbai. The public service menu is available. Online booking and payment are currently disabled.

## Website pages

- `/` — home, selected services, feedback carousel, contact and hours.
- `/our-story` — studio introduction.
- `/services` — Women, Men, and Beauty services categories.
- `/services/women`, `/services/men`, `/services/beauty` — searchable category menus. The older `/services/womens-hair` and `/services/mens` URLs still resolve.
- `/visit-us` — address, hours, call, WhatsApp and directions.
- `/book` — service, date and appointment-time flow; checkout stays unavailable until server readiness is approved.

Express serves the built client and `/api/*`. Client-side page routes use the History API; any separate static host must rewrite page requests to `client/dist/index.html` while keeping `/api/*` pointed at Express.

## Run locally

Requires Node.js 20.19+ and npm 10+.

```powershell
Copy-Item .env.example .env
npm install
npm run dev
```

Open <http://localhost:5173>. Vite proxies API calls to Express on port 5000. Keep real credentials in the ignored root `.env`, never in this README, source control, or chat. With the supplied mock notification settings and no provider credentials, the site can be browsed but will not take payments or send messages.

Useful checks:

```powershell
npm test
npm run build
```

## Service menu

The source of truth is [server/src/config/salon.js](server/src/config/salon.js). It currently contains 200 services: 34 Women, 30 Men, and 136 Beauty services. The category pages and cart use the same API catalog. Do not edit `client/dist/`; it is generated by the build.

[SERVICE_DATA_REVIEW.md](SERVICE_DATA_REVIEW.md) lists every configured service, current price, confirmation flag, source note, and missing duration. Four percentage-only offers have no payable amount. All 200 durations are unset, and the qualified staff roster/schedules have not been supplied. Do not invent either. [MENU_DATA_REVIEW.md](MENU_DATA_REVIEW.md) retains the scanned PDF page notes and earlier reconciliation details.

Menu display and booking approval are separate. A clear service with a price can be browsed and added to the local cart. Only a service with an approved customer name/inclusions, payable price, and positive duration can be bookable. The server automatically assigns an active employee who can perform every service in the cart and has enough free time. Customers do not select an employee.

## Booking and payment status

Online booking is intentionally **disabled** in `render.yaml` and the example environment. The application uses MongoDB transactions, 10-minute holds, per-employee 15-minute reservation locks, a fixed ₹100 advance (10,000 paise), Razorpay Checkout orders created for a held booking, signed webhooks, cancellation/refund tracking, and a notification outbox. The old standalone Razorpay Payment Button was removed because it accepted ₹100 without reserving the cart’s selected services and time.

Booking readiness fails closed until all of these are ready:

- A private transaction-capable MongoDB replica set or sharded deployment is reachable from the app.
- The menu has at least one bookable service; every service offered for booking has an approved name/inclusion, positive price and duration.
- Active staff records have approved service eligibility and complete weekly schedules; the salon schedule, breaks, holidays and blocked time are approved.
- `STAFF_ROSTER_APPROVED=true` is set only after the owner verifies those staff records.
- Razorpay API keys match the selected test/live mode, and the webhook secret and HTTPS webhook are configured.
- Real email or WhatsApp notification delivery is configured. The development mock does not send anything and cannot enable production booking.
- Booking and privacy policy versions are approved, and `BOOKING_ENABLED=true` is deliberately enabled for the appropriate environment.

No appointment is currently reservable and no payment should be collected through the website. Read [RAZORPAY_SETUP_GUIDE.md](RAZORPAY_SETUP_GUIDE.md), [DEPLOYMENT_RUNBOOK.md](DEPLOYMENT_RUNBOOK.md), and [MANUAL_QA_CHECKLIST.md](MANUAL_QA_CHECKLIST.md) before attempting staging or launch.

## Deployment

The existing Render preview is <https://dream-beauty-unisex-studio-karanjade.onrender.com/>. `render.yaml` keeps booking off. Provider credentials belong in Render’s secret environment settings, not Git. See the deployment runbook for Atlas access, Render configuration and custom-domain notes.
